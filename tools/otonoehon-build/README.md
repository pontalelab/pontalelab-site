# おとのえほん — テンプレート楽曲の作り方

`games/otonoehon/index.html` は単一HTMLファイル（ビルド不要・Vite等は使わない）で、
音声合成には Tone.js（CDN読み込み、外部依存はこれのみ）を使っている。

## 全体構成（画面遷移）

表紙 → モード選択 →（さるのブランコ／はちのふえの場合のみ）曲選択 → ゲーム画面

3つのゲームモード：
1. **さるのブランコ**：笛（メロディ）はテンプレート通り配置済み。振り子（さる）を自由に配置する
2. **はちのふえ**：振り子は1つ配置済み。笛は薄いガイド（🌸→🌼）をなぞって完成させる
3. **自由配置**：白紙の2ページから完全に自由に作る

## コアの仕組み

- **1ページ = 1小節**。`pages` 配列（各要素 `{objects, guides, allGuides}`）で管理
- **振り子**：始点=支点、終点=初期の振れ位置。画面下向きを鉛直として実際の振り子のように揺れる
  （`theta(t) = theta0 * cos(2πt/T)`、`theta0`はドラッグ角度を1.6倍に増幅）
- **笛**：始点/終点の座標から `flutePitch(len)`（Cメジャースケール2オクターブへ離散スナップ）で音程、
  `fluteTiming(o)`（x座標のみから計算）でタイミングを決定。**自由配置もテンプレートも全く同じ計算式**を使う
  （テンプレートは`guideShape()`が狙った音程になるよう長さを逆算して配置しているだけ）
- **テンプレート**：`index.html`内の`TEMPLATES`オブジェクトに `{pos, note, dur}`（拍単位）の配列で楽曲を定義。
  `guideShape()`が実際の座標に変換する
- **音源**：オブジェクトごとに専用のTone.Synthを1つずつ持たせる方式（`synthMap`）。
  複数オブジェクトで1つのシンセ/PolySynthを共有すると、同じ音程を近い時刻に重ねて予約した際に
  音が欠落するTone.js側の制約があるため、この設計にしている

## テンプレート楽曲の追加・差し替え方

このディレクトリの`midi-source/`にある元MIDIから、`midi-parse-scripts/`の簡易パーサ
（Python標準ライブラリのみ、外部ライブラリ不使用）で音符データを抽出し、
`games/otonoehon/index.html`内の`TEMPLATES`オブジェクトに手動で反映する運用にしている。

- `midi-source/bunbunbun.mid`（ぶんぶんぶん）→ `parse_midi.py` / `parse_melody.py`
- `midi-source/shabondama.mid`（シャボン玉）→ `parse_midi2.py` / `parse_melody2.py`

新しい曲を追加する場合も同様に、MIDIファイルをこのパーサで解析し、
`{pos, note, dur}`形式（拍単位）に変換して`TEMPLATES`へ手で追記する。

（今後の候補：MIDIファイルをアプリ内でアップロードして、その場でテンプレートを
自動生成する機能。現状は毎回この手動フローで反映している）

## 既知の問題・修正履歴（重要な学び）

- **`inset:0`** は一部モバイルWebViewで正しく解釈されないことがあった → `top/right/bottom/left`の
  明示指定に置き換え済み
- **`position:fixed` + `perspective` + `rotateY`の組み合わせ**は同WebViewで画面が全く表示されなくなる
  不具合を起こした → 現在は`position:absolute`すら使わず、通常のフロー内で`display:none/flex`を
  切り替えるだけのシンプルな方式にしている（アニメーションは opacity + 2D transform のみ）
- **画面遷移が非同期（フェード）になったことで、`resize()`が画面表示前に実行され、
  キャンバスの幅/高さが0のまま計算される**不具合があった → `showScreen(name, onShown)`に
  完了コールバックを追加し、実際に表示された後に`resize()`と初期化を行うよう修正済み
- **ページめくり演出（`animateFlipAway`）が毎小節ごとにキャンバスの高解像度スナップショットを
  作成しており、長時間ループさせると重くなる**問題があった → スナップショット解像度を50%に縮小し、
  演出の重複実行を防ぐガード（`flipInProgress`）を追加済み
- **長時間再生しているとAudioContextが一時停止（suspended）し、音が出なくなることがある**
  → `scheduleLoop`内で毎小節`Tone.context.state`をチェックし、止まっていれば自動的に
  `Tone.start()`で復帰させる処理を追加済み
